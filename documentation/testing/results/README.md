# Bench results (Gate G evidence)

This folder holds **measured** bench data only. It is empty until an assembled prototype is tested. Nothing in it
is generated by software: calculations and simulations are predictions and live elsewhere.

## Layout

```
documentation/testing/results/
  <board serial>/                 e.g. EVB-001 (the folder name must equal board.serial in every record)
    <test id>_<date>_<n>.json     one record per test run (schema nubm44-bench-result.v1)
    raw/                          raw instrument exports, scope captures, photos; never edited after recording
```

## Recording a test

1. Run the test from [test-plan.md](../test-plan.md) with the dummy load and the safety arrangements it requires.
2. Put the measured values in a CSV with the columns `quantity,value,unit` plus any condition columns (for example
   `vin_v`). Quantity names and units are those in [bench-tests.yaml](../bench-tests.yaml).
3. Import it; `--measured` is your statement that every value was measured on the bench:

   ```powershell
   .venv\Scripts\python.exe automation\bench\bench.py import-csv --test T1.4 --serial EVB-001 `
       --variant evaluation-board --hardware-revision A --firmware-revision <git sha> `
       --firmware-hex-sha256 <sha256 of firmware\build\nubm44_fw.hex> --operator "Name" `
       --instrument "DMM:<model>:<serial>:<calibration due>" --date 2026-11-20 `
       --condition ambient_c=23 --csv t14.csv --attach scope_3v7.png --measured
   ```

   `bench.py template --test T1.4 --serial EVB-001 --variant evaluation-board` prints an empty record if you prefer
   to write the JSON by hand (set `data_origin` to `MEASURED` only for real measurements).
4. Run `.venv\Scripts\python.exe automation\bench\bench.py check` (or `validate.py --mode bench`). It writes
   [reports/bench-report.md](../../../reports/bench-report.md) and `reports/bench-summary.json`.

## How records are judged

- The limits in `bench-tests.yaml` decide PASS or FAIL; predictions from the calculation and simulation evidence are
  shown beside the measurement and never decide a result.
- A record is INVALID when its metadata is incomplete, a raw file's SHA-256 no longer matches, its `data_origin` is not
  `MEASURED`, or the operator wrote PASS although a recorded value breaks a limit.
- Gate G closes for a board variant only when every test marked for that variant has a PASS record. Evaluation-board
  records never close the compact board.
- After a PASS, update the requirement status in `engineering/requirements.md` (NEEDS-TEST to VERIFIED-TEST) and run
  `scripts\validate.ps1`.
